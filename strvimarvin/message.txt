› what is this point about global tpe artifacts?


• That line is about an earlier, invalid-for-validation run style.

  There were two concepts:

  retrospective_global_research_only

  - One Optuna/TPE process could learn from a broader/global set of folds.
  - That is useful for parameter-family research.
  - But it is not clean live-style OOS validation, because optimizer state can be influenced by future folds relative to an earlier fold.
  - Any artifacts from that mode should be treated as research-only.

  point_in_time_fold_local

  - This is the repaired mode.
  - Every fold gets a fresh Optuna study.
  - The optimizer only sees that fold’s IS/training window.
  - Then the selected candidate is tested on that fold’s OOS window.
  - This is the mode used for the packaged 2024/2025 results.

  So the warning means: if the other LLM finds older run folders or code paths labeled global/retrospective, don’t use them as proof of clean OOS performance. For this handoff, they should run only:

  --optimizer-mode point_in_time_fold_local

  or rely on the default, which should be that mode.
